Overview

HorOS is an Arch Linux-based live ISO with a terminal setup wizard. The setup interface is a Fedora Anaconda-style summary screen, backed by archinstall --silent. This keeps Arch's flexibility without making you work through complex command-line steps.

Once installed, the system is a completely standard Arch: pacman, the standard directory layout, and standard systemd services. The HorOS-specific layer is limited to the installer, branding files, profiles, and limon integration.

HorOS is 64-bit only. 32-bit x86 and 32-bit UEFI are not supported.

Why is there no 32-bit support?

Arch Linux dropped 32-bit (i686) packages from its official repositories in 2017, and HorOS uses those repositories. Supporting 32-bit kernels, glibc, drivers, and desktop packages would require a separate source (Arch Linux 32) and a separate ISO build. The current profile is built on arch="x86_64" and packages.x86_64; the bootloaders are Syslinux for BIOS and x86_64 systemd-boot for UEFI.

A separate case is devices that use 32-bit UEFI despite having a 64-bit CPU (for example some Bay Trail or Cherry Trail tablets). These cannot run the x86_64 bootloader; they need an IA32 EFI bootloader and a 32-bit kernel. The current HorOS ISO does not include those, so it will not boot on such devices. If your firmware offers a 64-bit UEFI mode, select it.

Build the ISO

No ready-made ISO is distributed; to install, you first need to build the ISO yourself. Build it on an x86_64 Arch Linux system.

sudo pacman -Syu
sudo pacman -S archiso git base-devel qemu-desktop
git clone https://github.com/horoslinux/horcore.git
cd horcore
sudo ./build.sh          # clean build (default)
sudo ./build.sh --keep   # keep the work/ directory

The output is in out/. A clean build removes the work/ directory because mkarchiso can cache steps and skip profile changes.

Test the ISO

./test-qemu.sh            # BIOS
UEFI=1 ./test-qemu.sh     # UEFI (requires edk2-ovmf)

Installation

Once the ISO is ready, write it to USB, boot from it, and complete the summary in the terminal wizard. A typical install takes a few minutes, depending on download speed.

Write to USB and boot

Write the ISO you built to a USB device and boot from it.

Write to USB (Linux)

All data on the USB device will be erased. Replace /dev/sdX with your own device.

sudo dd if=horos-*.iso of=/dev/sdX bs=4M status=progress oflag=sync

Write to USB (Windows)

Select the ISO in Rufus or balenaEtcher and write the USB in GPT/UEFI mode (or MBR for BIOS).

Boot from USB

Select the USB device from your firmware menu. On UEFI systems, use 64-bit UEFI mode. The setup screen opens directly; no username or password is required.

Setup wizard

The screen is an Installation Summary. Select an item to change its settings, then press b to begin.

Summary itemWhat it does
1. KeyboardSet the keyboard layout (for example trq or us).
2. Time zoneConfirm or change the automatically detected time zone.
3. Installation profileChoose Server or Workstation.
4. Desktop environmentWorkstation only: terminal, KDE Plasma, or GNOME.
5. AI assistant (limon)The base install is always included; choose which provider SDK to add: Claude, OpenAI, or Gemini.
6. Installation targetSelect a disk, then choose full-disk or free-space installation.
7. Network and hostnameIf needed, configure Wi-Fi or networking with nmtui; set the hostname.
8. Root accountSet a root password or leave it locked.
9. Create userSet up your daily user and sudo access.
10. Swap spaceEnable or disable a swapfile on the ext4 root.
To start, choose b in the summary, then type INSTALL to confirm. When setup finishes, remove the USB and reboot.

After installation

# Update the system
sudo pacman -Syu

# Set the AI provider or API key
limon config

# Check network status
nmcli device status

See the disk layout section for details on disk modes.

Disk layout

Full-disk mode

  • UEFI: 512 MiB FAT32 ESP (/boot) and the remaining space as ext4 root.
  • BIOS: 1 GiB FAT32 /boot and the remaining space as ext4 root.

Install to free space

Existing partitions are preserved. A shared ESP is mounted without touching Windows boot files; the new root partition is created in the selected free space.

Swap

Swap is not a separate partition; it is created as a swapfile on the ext4 root. Its size is chosen based on the installer's RAM and enabled through /etc/fstab.

Full-disk mode erases all data on the selected disk. Back up before installing.

Profiles and desktop

Server

SSH open (22), all other incoming connections closed. Provides a minimal install for server and terminal use.

Workstation

All incoming connections closed. Desktop options:

  • Bare: terminal only
  • KDE Plasma: plasma-meta based desktop
  • GNOME: GNOME desktop

NVIDIA, Broadcom, and virtualization drivers are detected in the live environment as needed; if Wi-Fi is used, wpa_supplicant is added.

Packages and services

Included in every profile

nano, nftables, openssh, networkmanager, less, htop, curl, wget, bash-completion, man-db, man-pages, pciutils, usbutils, os-prober, fuse3, linux-firmware, and xdg-utils.

Enabled services

nftables.service, NetworkManager.service, systemd-timesyncd.service. On the Server profile, sshd.service is also enabled.

Security

The default nftables policy drops incoming connections. No service is exposed on Workstation; on Server, only SSH (22) is open.

limon AI assistant

limon is the AI-native part of HorOS and is included in every base install. Setup only asks which provider SDK to add:

  • Base only: choose the provider later with limon config
  • Claude
  • OpenAI
  • Gemini
  • All

The source tree is installed under ~/.limon, the virtual environment at ~/.limon/.venv, and the command at ~/.local/bin/limon. Installation is performed for both root and the created regular user.

limon config      # provider and API key
limon --help

Troubleshooting

Setup exits with code 99

Required items in the summary are incomplete: no disk selected, no administrator account, or no internet connection. Fix the relevant items and try again.

Setup exits with code 3

Boot validation failed. The kernel, initramfs, or GRUB/EFI files are not where expected. Repeat the install; if the problem continues, check /var/log/archinstall/install.log.

Setup exits with code 4

Branding files could not be copied. This is fixed in the current release. If an older install lost its KDE panel or bar:

rm -f ~/.config/plasma-org.kde.plasma.desktop-appletsrc
sudo rm -f /etc/skel/.config/plasma-org.kde.plasma.desktop-appletsrc

Then log out and back in; Plasma will recreate its default panel layout.

Setup asks for a network

Choose 7. Network and hostname in the summary, connect with nmtui, and try again.

UEFI system won't boot

Select 64-bit UEFI mode instead of 32-bit UEFI in your firmware. If Secure Boot is enabled, disable it temporarily and retry.
